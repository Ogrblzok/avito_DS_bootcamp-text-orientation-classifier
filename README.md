# Определение ориентации текстового кропа (0° / 180°)

> Решение выполнено в рамках технического задания **Data Science Bootcamp от Авито**

## Задача
Бинарная классификация: определить, повёрнут ли кроп с текстом на 180°.
Метрика: **1 − Brier Score**.

## Подход

**Модель**: `PP-LCNet_x1_0_textline_ori` (Apache 2.0, PaddleOCR).
Дообучение головы на собственной синтетике (~70к пар).

**Почему выбрана PP-LCNet_x1_0_textline_ori**:

- Специализирована под задачу — обучена именно на определение ориентации текстовой строки (0°/180°) на кропах от детектора, то есть на том же типе данных, что в тесте.
- Компромисс качество/скорость по ТЗ — 6.5 MB, ~5 ms на CPU. ТЗ требует компактности: модель применяется к сотням миллионов кропов в день. Крупные архитектуры дали бы +0.002–0.005 к Brier, но в 10–100 раз тяжелее — не оправдано.
- Хорошо дообучается на синтетике — голова переобучается за 7 эпох, backbone уже несёт полезные признаки текста.

**Ключевые решения генератора**:
- Независимая генерация примеров.
- Тёмные фоны (30%) + светлые.
- Реалистичные боксы детектора: асимметричные поля, обрезка краёв.
- Наклон ±5–8° (вместо ±15–30°, которые ломали обучение).
- JPEG-артефакты, шум, градиенты, размытие.

**Валидация**: псевдо-валидация на 2000 реальных тестовых кропах.
Для пары `(X, rot(X))` считаем symmetric 1 − Brier (min по двум гипотезам),
`rot_consistency` и долю уверенно различаемых пар.
